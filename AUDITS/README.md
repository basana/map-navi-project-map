# AUDITS — MAP NAVI

Store technical, UX, accessibility, security, data-quality, and release-readiness audits here.

## Required structure
- Date and audit scope
- Repository, branch, commit, and files examined (where applicable)
- Method and environment
- **Verified findings**
- **Potential risks / hypotheses** (clearly separated)
- Severity / user impact
- Evidence and reproduction steps
- Recommended action
- What was not inspected

An audit is evidence, not approval to implement. Record resulting approved decisions separately in `DECISIONS/`.

Suggested filename: `YYYY-MM-DD_topic_audit.md`.
